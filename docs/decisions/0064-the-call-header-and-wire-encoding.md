# 0064. The call header and the wire encoding

- **Status:** Proposed
- **Date:** 2026-11-25

## Context

[0013](0013-abnf-for-protocols-and-calls.md)'s 87-octet call header is "an illustrative example (not normative)". It names the object, interface and version in every call, and has no deadline. But versions are fixed at bind ([0014](0014-versioned-object-apis.md), rule 4), calls carry no token ([0015](0015-jwt-tokens-and-oidc-identity.md), rule 1), and every call that may cross the network carries a deadline ([0004](0004-network-transparency-and-failure.md), rule 3). [D25](../design/design-backlog.md#m2-kernel-objects) asks for the message types, the header, the length width, the largest message, and framing on IPC and QUIC. ADRs 0047 to 0061 set the transport: 960-octet messages ([0054](0054-ipc-endpoints.md), rule 3), sessions told apart by badge ([0049](0049-capability-spaces-rights-and-revocation.md), rule 5), and deadlines as counts locally and durations between nodes ([0051](0051-scheduling-timers-and-deadlines.md), rule 5).

On 2026-11-25 the project owner decided: messages are big-endian ([0062](0062-core-rules-big-endian-fixed-width.md), rule 2); a message carries up to three real capability transfers ([0066](0066-capability-parameters-and-server-streams.md), rule 3); and kernel interfaces are named under `aspis.kernel.`. Defaults that Claude proposed with these records, accepted the same day, shape rules 8 and 9: fault replies carry no register values, each holder of a session has its own badge, and stream pulls never block.

This record states decisions and invariants. The layouts, tables and grammar are in the [call-language specification](../design/call-language.md#the-call-header-and-wire-encoding), and where the two disagree, this record wins. No accepted record is edited with it. Claude drafted it on 2026-11-25.

## Decision

1. **Calls refer to bind state.** A call names no object, interface or version. On kernel IPC the session is the badge the kernel delivers; over RPC it is a session ID (rule 12). The manager's session table gives the object, interface, major and minor fixed at bind. The header carries no token, and no priority: that is scheduling-context donation ([0051](0051-scheduling-timers-and-deadlines.md), rule 3; [specification](../design/call-language.md#calls-refer-to-bind-state)).
2. **A message is one octet string, in memory order, on every transport.** Headers are whole 8-octet words, and the body starts on a word boundary. On kernel IPC the first four words travel in registers, each the big-endian reading of its octets; the kernel copies the rest without reading or swapping them. The kernel reports lengths in octets, not seL4's words, so every body has an exact end ([specification](../design/call-language.md#octets-and-words)).
3. **There are six message types:** request, reply, error reply, cancel, stream item and stream end. One-way is a property of a method, never a type or a flag ([specification](../design/call-language.md#message-types)).
4. **Word 0 is common to every message:** the protocol version, the type, the flags, the method number and the header length. Methods `0xFF00` to `0xFFFF` are protocol methods (rule 8). Some flag bits are must-understand: a receiver that doesn't know one rejects the message. The others are informational, and an unknown one is ignored. Whether a failed call ran is the error envelope's outcome ([0065](0065-typed-errors-and-minor-versions-on-the-wire.md), rule 5), never a flag ([specification](../design/call-language.md#word-0)).
5. **The IPC request header is four words**, seL4 AArch64's fast registers: word 0, a deadline, and a 16-octet request ID. Every request carries both: a client can't tell a proxy endpoint from a local one ([0004](0004-network-transparency-and-failure.md), rule 2). The deadline is an absolute virtual count, 0 for none. The request ID is opaque, compared only for equality, reused by a retry, and all zero only when the kernel sends ([specification](../design/call-language.md#the-ipc-request)).
6. **Replies, error replies, stream items and stream ends are word 0, then the body.** The reply object or the call's QUIC stream ties them to the call, so they carry no request ID ([specification](../design/call-language.md#replies-errors-and-stream-messages)).
7. **A cancel is advisory, and IPC only.** After a call returns "canceled" or "timed out" following delivery, the library sends word 0 and the request ID with the non-blocking send, on the same session capability. The invalidated reply object stays the guarantee ([0054](0054-ipc-endpoints.md), rule 6). Over QUIC the stream is reset ([specification](../design/call-language.md#cancel)).
8. **Protocol methods ride any session** and aren't Cedar actions: `stream_next`, `stream_close`, `stream_ready`, `session_close` and `session_dup`, and, between network servers only, `export_release`, `export_read` and `export_ended`. `stream_next` never blocks, and `session_close` releases only its own badge ([0066](0066-capability-parameters-and-server-streams.md), rules 5 and 8; [specification](../design/call-language.md#protocol-methods)).
9. **Messages the kernel sends are ordinary requests**, with deadline 0 and an all-zero request ID, as methods of the `[local]` interfaces `aspis.kernel.fault/1` (one method per fault kind), `aspis.kernel.pager/1` and `aspis.kernel.memory_request/1`. Page and memory requests are one-way. The kernel reads no reply: a fault's reply only resumes the thread, and a handler changes registers through the thread's capability first ([0061](0061-debugging.md)). That departs from seL4 ([0047](0047-the-kernel-follows-sel4.md), rule 3) and keeps [0054](0054-ipc-endpoints.md), rule 4 true. Their dispatchers hand anything unknown to the handler and send nothing by default, so an unknown fault kind stays fatal ([specification](../design/call-language.md#messages-the-kernel-sends)).
10. **Header extensions** follow a request's fixed header. Each is whole words, and its kind says whether it is critical. An unknown critical kind is refused, and an unknown other kind skipped. W3C trace context travels as one, in binary. Only requests carry extensions, and a request header is at most 32 words ([specification](../design/call-language.md#header-extensions)).
11. **Spilling is IPC only.** A request, reply or stream item too big to send inline sets `spilled`, and its body becomes an offset and length into a memory object that travels as the last capability, so no other index moves. Error replies and stream ends never spill. A method that may spill, judged against the largest header, declares at most two capabilities in that direction ([specification](../design/call-language.md#spilling)).
12. **RPC is one QUIC stream per call.** A frame holds its length, a table of up to three capability descriptors ([0066](0066-capability-parameters-and-server-streams.md), rule 4), then the message ([QUIC framing](../design/call-language.md#quic-framing)). The RPC request adds a fifth word: a session ID that the remote network server mints at bind, scoped to the peer. The deadline is the nanoseconds remaining. Cancels and failures are stream resets, mapped onto ADR 0004's outcomes: unreachable before the request is fully written, indeterminate after ([specification](../design/call-language.md#the-rpc-request)).
13. **Network servers translate headers and never parse bodies.** The client's network server adds the session ID, converts the deadline, inlines spilled bodies, and turns capabilities into descriptors, all or nothing; a call it can't translate fails locally as unreachable. The server's network server reverses this. After IPC to RPC to IPC, the method, request ID, extensions, body and every flag but `spilled` are unchanged ([specification](../design/call-language.md#what-network-servers-translate)).
14. **A message is at most 2^24 octets (16 MiB)** on either transport. The compiler and every receiver enforce it. Lengths and counts are `u32` ([0062](0062-core-rules-big-endian-fixed-width.md), rule 6). Bulk data goes through memory objects or streams, and raising the limit needs a new protocol version ([specification](../design/call-language.md#size-limits)).

## Consequences

- **D25 is settled:** message types (rule 3); bind state, not repeated IDs (rule 1); the deadline and session reference (rules 5 and 12); flags (rule 4); trace context (rule 10); the length width and largest message (rule 14); framing (rules 2 and 12). Open in the specification: request-ID uniqueness, the reply cache and default deadlines ([L04](../design/call-language.md#l04-request-ids-the-reply-cache-and-default-deadlines)); the bind message ([L05](../design/call-language.md#l05-the-bind-message)); the ALPN identifier and reset-code values ([L06](../design/call-language.md#l06-the-alpn-identifier-and-reset-codes)); when trace context is set ([L09](../design/call-language.md#l09-tracing)); raising the limit ([L25](../design/call-language.md#l25-the-message-size-limit)).
- **ADRs 0047 to 0061 change to match**, in the same pull request: [0054](0054-ipc-endpoints.md), rules 4 to 6 and [0051](0051-scheduling-timers-and-deadlines.md), rule 5 cite this record; [0056](0056-faults-and-page-fetch-deadlines.md), rule 2 drops register values from fault replies, and [0047](0047-the-kernel-follows-sel4.md), rule 3 records the departure; the [kernel specification](../design/kernel-specification.md#k28-message-and-buffer-layout) gives lengths in octets, and says whether a "timed out" or "canceled" message was delivered.
- **Departures from the D25 research:** no one-way or "not executed" flag, the spill object last, and extensions on requests only.
- The header is a trust-boundary parser, so C18 and C29 bring fuzz targets for it ([0068](0068-the-fuzzing-and-differential-testing-gate.md)).
